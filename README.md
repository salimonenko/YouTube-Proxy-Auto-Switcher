# YouTube-Proxy-Auto-Switcher
A Microsoft Edge browser extension (Manifest V3) that automatically retrieves proxy servers from an external API, verifies their functionality, and configures the browser so that **only YouTube domains** are routed through a proxy, while all other traffic proceeds directly. Tested in Microsoft Edge 109  (64-bit) on the Windows 7 operating system.

# YouTube Proxy Auto-Switcher

Расширение для Microsoft Edge (Manifest V3), которое автоматически получает прокси-серверы из внешнего API, проверяет их работоспособность и настраивает браузер так, чтобы **только домены YouTube** шли через прокси, а остальной трафик — напрямую. Проверена работа в браузере Edge 109 (Official build) (64-bit) в операционной системе Windows 7.

**Цель:** более стабильное и быстрое воспроизведение видео на YouTube за счёт выбора рабочего прокси-маршрута. Расширение не предназначено для обхода блокировок и не претендует на анонимность — оно лишь выбирает маршрут доступа к YouTube.

## Возможности

- Автоматический запрос прокси у внешнего API (`IP:port`).
- Проверка живости прокси через `chrome.webRequest` (реальный HTTP-статус, а не opaque `no-cors`).
- PAC-скрипт: через прокси идут только запросы на: `youtube.com`, `googlevideo.com`, `ytimg.com`, `ggpht.com`, `youtube-nocookie.com`. Остальное — `DIRECT`.
- Автоматическая смена прокси при сбое: по событиям `<video>` (`waiting`/`playing`), по `online`/`offline`, по периодической проверке.
- Сохранение текущего прокси в `chrome.storage.local` — переживает «усыпление» service worker и перезапуск браузера.
- UI-уведомления на странице YouTube (сообщения) о смене прокси, исчерпании списка и ошибках API.

## Как это работает

1. `background.js` (service worker) при установке, старте браузера или по сигналу от `content.js` запрашивает новый прокси у API.
2. Полученный `IP:port` применяется через `chrome.proxy.settings.set` в режиме `pac_script`.
3. PAC-скрипт направляет через прокси только домены YouTube; остальное — напрямую.
4. Проверка живости: `chrome.webRequest.onCompleted` / `onErrorOccurred` для `https://www.youtube.com/*`. Статус `200–399` — жив, `407/502/...` или сетевая ошибка — мёртв.
5. Если прокси мёртв — запрашивается следующий. Если список исчерпан (HTTP 406 от API) — PAC сбрасывается, YouTube идёт напрямую, а цикл proxyLifecycle завершается. При следующем событии (onStartup, onInstalled или сигнал check_connection от content.js) расширение снова запросит прокси у API — если API к этому моменту снова выдаёт адреса, работа продолжится; если по-прежнему 406, PAC останется сброшенным до следующего события.
6. `content.js` следит за `<video>` и при долгой буферизации просит `background.js` проверить/сменить прокси.

## Установка (Edge, режим разработчика)

1. Скачайте репозиторий.
2. Разместите файлы manifest.json, background.js, content.js в какой-нибудь папке, НЕ являющейся системной. Хоть на рабочем столе или в документах.
3. Запустите браузер Edge, откройте `edge://extensions/`.
3. Включите в браузере **«Режим разработчика»**.
4. Нажмите **«Загрузить распакованное расширение»** (Load unpacked) и выберите папку с `manifest.json`.
5. Расширение появится в списке расширений браузера. После чего нужно включить его путем нажатия флажка справа от его наименования. После перезапуска Edge его может потребоваться включить расширение вручную — это штатное поведение Edge для распакованных расширений. Которые НЕ опубликованы в магазине Google Store. 

> **Важно:** не копируйте папку расширения в системный каталог Edge (например, `%LOCALAPPDATA%\Microsoft\Edge\User Data\...`) — браузер удалит её при очередном запуске. Держите папку в постоянном месте, например `D:\EdgeExtensions\YouTubeProxyAutoSwitcher\`.

6. Обновите страницу YouTube (F5). Без этого расширение не заработает. 

## Настройка API

Потребуется запуск PHP-сервера на локальном компьютере на домене myextension.local. Для проверки, ссылка http://myextension.local:8000/IP_port_value.php должна открываться браузером.
Кроме того, потребуется список-перечень прокси-серверов в файле proxy.txt. Список должен выглядеть примерно следующим образом, каждая строчка имеет вид IPaddress:port):
1.2.3.4:8080\
4.5.7.89:10508\
5.3.77.92:30245

Чем больше прокси-серверов, тем лучше. 
При очередном запросе к IP_port_value.php (локальный) сервер должен выдавать либо строку вида IPaddress:port, например, 4.5.7.89:10508, либо сообщение об ошибке. Последнее служит сигналом для браузера - возобновить перебор этого списка с начала.

## Разрешения (из файла manifest.json):

proxy — управление настройками прокси браузера (PAC-скрипт).
webRequest — наблюдение за HTTP-статусом запросов к YouTube для проверки живости прокси.
storage — сохранение текущего прокси между перезапусками service worker.
tabs — отправка сообщений во вкладки YouTube.
host_permissions ограничены доменами YouTube и адресом API.

## Ограничения:

Расширение проверялось на Edge 109 (Windows 7, последняя поддерживаемая версия Edge для Win7). На современных версиях Edge должно работать, но не тестировалось.

API должен быть доступен; при недоступности API уже установленный PAC, сохраненный в браузере, продолжает действовать, пока прокси жив.
Расширение не обеспечивает анонимность и не предназначено для обхода блокировок.

## Безопасность и конфиденциальность

Расширение направляет через прокси-сервер только трафик к доменам YouTube (youtube.com, googlevideo.com, ytimg.com, ggpht.com, youtube-nocookie.com). Остальной трафик в интернет идёт напрямую, без использования прокси-сервера.
Расширение не обеспечивает анонимность и не предназначено для обхода блокировок. Оно лишь выбирает маршрут доступа к YouTube.
Расширение направляет через прокси-сервер только трафик к доменам YouTube. Соединение с прокси устанавливается по HTTP (директива PROXY в PAC-скрипте), но запросы к YouTube идут по HTTPS через туннель CONNECT. Это означает, что прокси-сервер видит домены, к которым вы подключаетесь, и объём трафика, но не видит содержимое HTTPS-запросов и cookies — они защищены TLS-шифрованием между браузером и YouTube.
Прокси видит не вас, как «пользователя», в смысле личности, а факт и время подключения с вашего IP-адреса к YouTube.
Если прокси-сервер не принадлежит вам и не контролируется вами, он всё равно может видеть, что вы заходите на YouTube, и в какое время. Используйте только доверенные прокси.
